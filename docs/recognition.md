# 识别、候选与执行细节

## 为什么采用三层结构

每一步都把整局信息交给 DeepSeek 自由判断，会遇到网络延迟、动作不稳定和口播漂移。项目因此拆成视觉与执行、本地规则与正式推荐、DeepSeek 有限改选与中性素材三层。

本地提示词要求优先采用正式推荐，只有明显更差时才允许改选并说明原因。候选固定为“正式推荐＋最多两个按真实评分排序的备选”，不为了凑三手补动作。

正式推荐是合法非 `pass` 时，不会把“过”放进 DeepSeek 候选；正式推荐为“过”时才保留“过”及其他合法备选；没有任何合法出牌时只有“过”。

## 视觉识别与 OCR 回退顺序

不同区域使用不同方法，不能用“有没有调用 OCR”判断实际耗时。

| 场景 | 识别与回退顺序 | 日志/备注 |
| --- | --- | --- |
| 叫地主、不叫按钮 | 先匹配 `templates/mini_ui_buttons/` 的两个模板；任一命中即返回，否则 RapidOCR | 模板命中时 `source=template`，回退时为 `rapidocr`；决策日志的 `point_source` 保留真实来源 |
| “提示”按钮 | 直接 RapidOCR；找不到再用已知相对位置兜底 | 不使用叫牌按钮模板 |
| 两位数徽章 | 直接 RapidOCR；仅接受 10–20 | 读数异常时按记账规则复核 |
| 个位数徽章 | RapidOCR 与 0–9 模板交叉验证；OCR 无数字时可单独使用模板 | 最高分 ≥0.72 且与次高分差 ≥0.04；OCR 与模板冲突时拒绝，个位数还需连续两次一致 |
| 取消托管 | 在局部区域做模板匹配，超过 0.7 才点击 | 没有 OCR 回退，模板缺失则停手 |
| 大厅、弹窗、结算文字 | `ocr_words.ps1` 调用 Windows.Media.Ocr | 用于整页文字、按钮定位及结果交叉确认；失败时未知页面不点击 |
| 手牌和桌面牌点 | `mini_skin`、`table_skin` 的形状与模板匹配，普通牌颜色无关，大小王保留颜色证据 | 不是 RapidOCR；不可靠时先重新截图，再进入保护兜底 |
| 时钟、地主标记、胜负等 | 颜色探针与相对位置 | 不属于文字识别 |

按钮模板实测约 0.03 秒，按钮 RapidOCR 约 2–4 秒，单个徽章约 0.2–0.4 秒；Windows 场景 OCR 还会启动 PowerShell 子进程。RapidOCR 引擎只延迟初始化一次，不是每次重新创建。

叫牌按钮采用两类去重：

- 像素完全相同的画面在 1 秒内复用识别结果；画面变化立即重新识别。
- 同一阶段、同一动作达到两次点击上限后，在再次读牌和 OCR 前直接 `bid_click_deduped`。

排查时先检查 `point_source` 和按钮项 `source`，不要把历史日志中的 `rapidocr_button` 理解为“每次都走 OCR”。不要绕过保护另写窗口识别或取消点击去重。

## 手牌与桌面识别

- 普通牌使用与颜色无关的形状匹配，只有大小王保留颜色证据辅助区分。
- 叫牌、领出和跟牌共用二次识别：首次点数不可靠或读取失败时，等待 0.3 秒重新截图再读一次，第二次仍不可靠才进入保护兜底。
- 最右侧“地主”角标通过末尾孤立高轮廓过滤，不直接排除最右一张手牌。
- 两位数徽章使用 OCR；个位数使用 OCR 与真实模板交叉验证。连续出牌按当前牌面首次出现时间去重，旧徽章不会阻止下一手扣牌。
- 目标最多读取 3 帧；`pass_only` 自动过牌前额外复核两帧。

程序只能看到当前窗口中的公开信息，不读取游戏内存，也不知道其他玩家的暗牌。

## 策略与拆炸逻辑

- 领出和跟牌评估会惩罚拆残炸弹；双王只剩一张也计入拆炸。
- 普通跟牌若所有非炸弹候选都会拆炸，完整炸弹会参与成本比较，避免为保一组炸弹而拆残另一组。
- 三带一在最低带牌拆炸时提供不拆炸的替代带牌。
- `bot_cli.mjs` 将 `bot.js` 正式动作按具体卡牌精确匹配，即使不在 `local_score` 前六名也保留在候选中。
- 四带二的两张单牌可以同点数，合法四带两对保留；提前消耗完整炸弹的领出偏好未在本轮调整。

## 选牌、提示与执行保护

- 每批最多选择 3 张，批后回读并累计选中状态，只补剩余牌；残余选择不明时停止本手。
- 识别不可靠时优先 OCR 定位游戏“提示”，失败后使用已知位置兜底。
- 非法桌面目标保存 `follow_target_invalid` 现场和计数信息，同时继续使用游戏提示完成本手，避免倒计时后系统托管接管。
- 全黑截图不会被接受：记录 `capture_black_frame`、尝试另一捕获方式，连续失败后停手。
- 出牌后检查手牌数和状态；失败只进行有限重试，不无限重复提交。
