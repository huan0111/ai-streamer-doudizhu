# Windows、截图与 DPI

> **本项目不是在任意电脑、分辨率或 Windows 缩放比例下都能即插即用。** 坐标会按客户区换算，但卡牌字形、颜色探针、OCR 和模板仍依赖实际渲染效果。尚未验证的环境必须先自检，再人工盯着试玩一局；不要直接无人值守或连续开局。

## 客户区与坐标

程序不是按整个桌面找固定屏幕坐标：

1. 按窗口标题“腾讯欢乐斗地主”和窗口类名 `Chrome_WidgetWin_0` 找到小程序窗口。
2. 通过 Windows `GetClientRect` / `ClientToScreen` 获取客户区实际大小及左上角屏幕位置。
3. 手牌与模板识别以 `933×580` 为历史基准使用统一比例，不分别拉伸宽、高；按钮模板在相应局部区域搜索。
4. 最终屏幕坐标根据识别到的实际位置映射回客户区。窗口移动后重新读取左上角，点击前还会复核客户区尺寸。

`933×580` 只是历史基准图，不表示窗口曾从 580 动态变为其他尺寸。真实客户区以当次 Windows 测量为准。

## 已验证与未验证环境

- Windows 显示缩放 125%、DPI 120 下，实机覆盖 `933×620`、`1017×627`、`1031×641` 和 `1035×645`；历史自检图另覆盖 `933×580`。
- 客户区小于 `933×580` 会停止点击，避免在裁切画面上乱点；不要通过自动拉伸窗口绕过保护。
- 更大的窗口和非等比例画面有坐标换算，但字形、颜色探针及模板仍可能受影响，不能直接视为兼容。
- 多显示器、不同显示器使用不同 DPI 的场景尚未验证；首次试玩建议加 `--no-overlay`。

## DPI 注意事项

主程序会调用 `SetProcessDpiAwareness(2)`。不要在主播进程里重复做窗口尺寸拦截：`mini_bot.py` 只在它自己的进程里设置 DPI 感知，不会把设置传给主播进程。

最稳妥的方式是直接启动 `mini_bot.py` 并消费事件，使用它记录的 `client_size`、`image_size` 和 `capture_method`。

如果必须自行读取窗口尺寸，必须在该进程的任何 Win32 窗口或截图调用之前设置 `SetProcessDpiAwareness(2)`，并用物理像素检查客户区。否则在 125% 缩放下，真实的 `1017×627` 可能被读成 `813×501`，从而被错误地当成“窗口太小”。

## 截图失败与窗口变化

- 截图与客户区尺寸不一致时记录 `capture_size_mismatch`，重新捕获并尝试 ImageGrab。
- 尺寸正确但全黑的画面记录 `capture_black_frame`，尝试另一捕获方式；连续失败会停手，不会用黑图继续识别。
- 日志分别记录客户区、窗口外框、截图、DPI 和捕获方式。
- 运行中改变客户区尺寸会触发 `window_resized` 并放弃该次点击；调整后先保持窗口稳定，再重新开始试玩。
- 窗口只移动且尺寸不变时，点击前使用新的 `live_bbox`。
- 移动窗口导致当前一手失败属于可接受限制；窗口稳定后，下一轮重新截图并恢复识别。ImageGrab 截图过程中的移动竞态没有被当作已发生故障。

## 浮窗

浮窗会跟随窗口几何变化重新放置；屏幕没有足够空间时会隐藏，不覆盖游戏客户区。多显示器和不同 DPI 组合尚未完整验证。
