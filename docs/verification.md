## 识别路径与耗时

同一 CPU 上的实际抽样：

- 叫牌按钮模板命中约 0.03 秒。
- 按钮 RapidOCR 实测约 2–4 秒。
- 单个徽章约 0.2–0.4 秒。
- Windows 场景 OCR 需要启动 PowerShell 子进程，未将其耗时伪装成已测量数据。

RapidOCR 引擎只延迟初始化一次。主循环还会周期读取徽章，因此需要结合 `point_source`、按钮项 `source` 和实际耗时判断瓶颈。

## 实机覆盖

已进行多局真实牌局，包含胜利和失败。实际覆盖过：

- 从旧版和新版大厅自动进入斗地主合集、选择新手场并开始游戏。
- 长牌分批选择、跨批纠偏、普通对子、大小王、连对、三带一、四带二和合法四带两对。
- 跟牌与领出、系统托管取消、结算识别和单局退出。
- 简洁牌桌完整单局：多次手牌完整识别，四带二、四带两对、对子和单张均执行确认；未出现手牌二次识别失败、选牌未确认、非法目标、黑图或尺寸异常。
- 新版补助结算浮层曾将“继续游戏”识别为“继游戏”，已增加容错并用真实保存结算图验证单局退出判断。
- 没有将某局胜负当成识别正确率或策略胜率的统计证明。

以下边界仍未被实机充分覆盖：

- 队友出 8 张飞机后只剩 1 张的精确场景未再次自然出现；非法目标留证和提示兜底不能当作桌面飞机视觉问题已经修复的证明。
- 王炸指定样例通过确定性引擎和候选回归，但未在自然牌局中再次遇到同样牌型。
- 移动窗口导致当前一手失败属于可接受限制；窗口稳定后下一轮重新截图恢复。多显示器、其他 DPI、微信版本和皮肤仍需单独验证。

这些记录用于说明功能曾被真实执行，不代表其他环境可以直接无人值守运行。

## 测试命令

```powershell
node --test vendor/dsh-doudizhu/test/bot.test.mjs vendor/dsh-doudizhu/test/rules.test.mjs
```

当前结果：

- `mini_selftest.py`：276 项，0 失败。
- 上游 bot/rules 测试：38/38 通过。

公开自检使用 `samples/selftest/` 中的 52 张脱敏图片，不需要真实 `api_config.json`、API 密钥或打开游戏。

**离线自检通过不等于当前电脑实机兼容。** 新环境仍应先运行自检，再人工监督完成一局。
